# 第13章：セキュリティスキャンの仕組み

[← ハンズオン目次](README.md)

## 何をするか

登録したサイトの **セキュリティ状態をチェック** する機能の仕組みを理解します。バージョン確認、不審なコードパターンの検出、推奨事項の生成を行います。

## なぜこの機能か

- **脆弱性の早期発見**：古い WordPress / PHP / プラグインは既知の脆弱性を抱えていることが多い。バージョンを把握することで、更新の必要性を判断できる。
- **マルウェア検出**：外部からコピーしたテーマ/プラグインに、`eval()` や `base64_decode()` などの不審なコードが含まれていないかチェック。
- **運用のベストプラクティス**：未使用のプラグインを削除するなど、セキュリティリスクを減らすための推奨事項を提示。

## 主なファイルと役割

| ファイル | 役割 |
|----------|------|
| `src/app/api/sites/[id]/security/scan/route.ts` | セキュリティスキャン API |
| `src/types/index.ts` | スキャン結果の型定義 |

## 処理の流れ

1. **バージョン情報取得**：サイトが起動中なら、WP-CLI でコア/PHP/プラグイン/テーマのバージョンを取得。
   ```bash
   docker compose run --rm wpcli core version
   docker compose run --rm wpcli plugin list --format=json
   docker compose run --rm wpcli theme list --format=json
   ```

2. **ファイルスキャン**：`wp-content/plugins` と `wp-content/themes` 内の `.php` / `.js` ファイルを走査し、不審なパターンを検出。

3. **推奨事項生成**：検出結果に基づいて、セキュリティ上の推奨事項を生成。

4. **結果返却**：バージョン情報、検出された問題、推奨事項をまとめて JSON で返す。

## 検出パターン

### PHP

| パターン | 危険性 |
|----------|--------|
| `eval()` | 任意コード実行。マルウェアに頻出 |
| `base64_decode()` | コードの難読化に使われる |
| `gzinflate()` | 圧縮されたマルウェアの展開 |
| `preg_replace(.../.../e)` | e 修飾子による任意コード実行 |
| `exec()`, `shell_exec()`, `system()`, `passthru()` | シェルコマンド実行 |

### JavaScript

| パターン | 危険性 |
|----------|--------|
| `eval()` | 任意コード実行 |
| `document.write()` | XSS に悪用されやすい |
| `innerHTML =` | XSS に悪用されやすい |

## ポイント

### 誤検知への対応

正規のプラグインでも `eval()` を使うケースはある（例: テンプレートエンジン）。検出されたからといって即マルウェアとは限らない。ファイルパスと行番号を表示し、目視で確認できるようにしている。

### スキャンの除外

`node_modules/`, `vendor/`, `.git/` は除外。これらは外部ライブラリであり、スキャンしても意味がない上に時間がかかる。

### 起動していないサイト

サイトが停止中の場合、WP-CLI が使えないためバージョン情報は取得できない。その場合は `versionSkippedReason` にその旨を返し、ファイルスキャンのみ実行する。

## 確認

- サイトカードの「セキュリティ」をクリック。
- 「スキャン実行」でバージョン情報と検出結果が表示される。
- 不審なパターンが見つかった場合、ファイルパスと行番号が表示される。
- 「推奨事項」に、無効化されたプラグインの削除などが表示される。
